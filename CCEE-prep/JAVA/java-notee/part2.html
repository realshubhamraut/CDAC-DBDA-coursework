1. Classes and Objects

Class Definition

class ClassName {
    // Fields (Instance Variables)
    int field1;
    String field2;
    
    // Constructor
    ClassName() {
        // initialization
    }
    
    // Methods
    void method1() {
        // code
    }
}

Creating Objects

// Declaration + Instantiation + Initialization
ClassName obj = new ClassName();

// Access members
obj.field1 = 10;
obj.method1();

Constructors

class Person {
    String name;
    int age;
    
    // Default constructor
    Person() {
        name = "Unknown";
        age = 0;
    }
    
    // Parameterized constructor
    Person(String name, int age) {
        this.name = name;   // 'this' refers to current object
        this.age = age;
    }
    
    // Copy constructor (manual)
    Person(Person p) {
        this.name = p.name;
        this.age = p.age;
    }
}

Constructor Overloading

class Box {
    int length, width, height;
    
    Box() { length = width = height = 1; }
    Box(int side) { length = width = height = side; }
    Box(int l, int w, int h) { length = l; width = w; height = h; }
}

this Keyword

  • Refers to current object
  • Distinguish instance variables from parameters
  • Call another constructor: this()
  • Pass current object as argument
  • Return current object
class Example {
    int x;
    
    Example(int x) {
        this.x = x;  // this.x is instance, x is parameter
    }
    
    Example() {
        this(10);    // calls parameterized constructor
    }
}
Key: If no constructor defined, Java provides default constructor. If you define ANY constructor, default is NOT provided!
2. Encapsulation

What is Encapsulation?

Bundling data (fields) and methods that operate on data into a single unit (class), and restricting direct access to some components.

Access Modifiers

Modifier Class Package Subclass World
private ✓ ✗ ✗ ✗
default (no modifier) ✓ ✓ ✗ ✗
protected ✓ ✓ ✓ ✗
public ✓ ✓ ✓ ✓

Getters and Setters

class Person {
    private String name;
    private int age;
    
    // Getter
    public String getName() {
        return name;
    }
    
    // Setter with validation
    public void setAge(int age) {
        if (age > 0) {
            this.age = age;
        }
    }
    
    public int getAge() {
        return age;
    }
}

Benefits of Encapsulation

  • Data hiding and protection
  • Flexibility to change implementation
  • Control over data (validation)
  • Easy to test and maintain
MCQ Tip: Encapsulation = private fields + public getters/setters
3. Inheritance

What is Inheritance?

Mechanism where a new class (child/subclass) inherits properties and behaviors from existing class (parent/superclass).

extends Keyword

class Animal {
    String name;
    void eat() { System.out.println("Eating..."); }
}

class Dog extends Animal {
    void bark() { System.out.println("Barking..."); }
}

Dog d = new Dog();
d.name = "Buddy";   // inherited
d.eat();            // inherited
d.bark();           // own method

Types of Inheritance

Type Description Supported?
Single One parent, one child ✓
Multilevel Chain: A → B → C ✓
Hierarchical One parent, multiple children ✓
Multiple Multiple parents (classes) ✗ (use interfaces)
Hybrid Combination ✗ (for classes)

super Keyword

class Parent {
    int x = 10;
    Parent() { System.out.println("Parent constructor"); }
    void show() { System.out.println("Parent show"); }
}

class Child extends Parent {
    int x = 20;
    
    Child() {
        super();  // calls parent constructor (must be first line!)
        System.out.println("Child constructor");
    }
    
    void show() {
        System.out.println(super.x);  // 10 (parent's x)
        System.out.println(this.x);   // 20 (child's x)
        super.show();                 // calls parent's show()
    }
}

Method Overriding

class Animal {
    void sound() { System.out.println("Some sound"); }
}

class Dog extends Animal {
    @Override   // annotation (optional but recommended)
    void sound() { System.out.println("Bark"); }
}

Overriding Rules

  • Same method name and parameters
  • Return type: same or covariant (subtype)
  • Access modifier: same or less restrictive
  • Cannot override: static, final, private methods
  • Can throw: same or narrower exceptions
Key: Java doesn't support multiple inheritance with classes to avoid Diamond Problem. Use interfaces instead!
4. Polymorphism

What is Polymorphism?

Ability of an object to take many forms. Same method behaves differently based on the object.

Two Types

Compile-time (Static) Runtime (Dynamic)
Method Overloading Method Overriding
Resolved at compile time Resolved at runtime
Same class Parent-child classes

Method Overloading

class Calculator {
    int add(int a, int b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
    double add(double a, double b) { return a + b; }
}

// Overloading based on:
// 1. Number of parameters
// 2. Type of parameters
// 3. Order of parameters
// NOT based on return type alone!

Method Overriding (Runtime Polymorphism)

class Shape {
    void draw() { System.out.println("Drawing shape"); }
}

class Circle extends Shape {
    @Override
    void draw() { System.out.println("Drawing circle"); }
}

class Square extends Shape {
    @Override
    void draw() { System.out.println("Drawing square"); }
}

// Runtime polymorphism
Shape s1 = new Circle();
Shape s2 = new Square();
s1.draw();  // "Drawing circle"
s2.draw();  // "Drawing square"

Upcasting and Downcasting

// Upcasting (implicit) - child to parent
Animal a = new Dog();  // OK

// Downcasting (explicit) - parent to child
Dog d = (Dog) a;       // OK if 'a' actually refers to Dog

// Check before downcasting
if (a instanceof Dog) {
    Dog d = (Dog) a;
}
MCQ Tip: Overloading = compile-time = same class. Overriding = runtime = inheritance.
5. Abstraction

What is Abstraction?

Hiding implementation details and showing only essential features. Achieved through abstract classes and interfaces.

Abstract Class

abstract class Animal {
    String name;
    
    // Abstract method (no body)
    abstract void sound();
    
    // Concrete method (has body)
    void sleep() {
        System.out.println("Sleeping...");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Bark");
    }
}

// Cannot instantiate abstract class
// Animal a = new Animal();  // ERROR!
Animal a = new Dog();        // OK

Abstract Class Rules

  • Cannot be instantiated
  • Can have abstract and concrete methods
  • Can have constructors, fields, static methods
  • Child must implement all abstract methods (or be abstract itself)
  • Can have final methods (cannot be overridden)

Abstract vs Concrete

Abstract Class Concrete Class
abstract keyword No abstract keyword
Can have abstract methods All methods have body
Cannot instantiate Can instantiate
Meant to be extended Can be final
Key: If a class has even ONE abstract method, the class MUST be declared abstract!
6. Static Members

Static Variables

class Counter {
    static int count = 0;  // shared by all objects
    int id;
    
    Counter() {
        count++;
        id = count;
    }
}

Counter c1 = new Counter();  // count = 1
Counter c2 = new Counter();  // count = 2
System.out.println(Counter.count);  // 2 (access via class name)

Static Methods

class MathUtils {
    static int add(int a, int b) {
        return a + b;
    }
}

// Call directly with class name
int sum = MathUtils.add(5, 3);

Static Method Restrictions

  • Cannot use this or super
  • Cannot access non-static members directly
  • Cannot be overridden (but can be hidden)

Static Block

class Example {
    static int x;
    
    // Static block - runs once when class is loaded
    static {
        x = 10;
        System.out.println("Static block executed");
    }
}

Static Import

import static java.lang.Math.*;

double result = sqrt(16);  // No need for Math.sqrt()
MCQ Tip: Static methods cannot access instance variables directly. They need an object reference.
7. final Keyword

final Variable

final int MAX = 100;
MAX = 200;  // ERROR! Cannot reassign

// Blank final - assigned in constructor
class Example {
    final int x;
    Example(int x) {
        this.x = x;  // Must initialize
    }
}

final Method

class Parent {
    final void show() {
        System.out.println("Cannot override");
    }
}

class Child extends Parent {
    void show() {}  // ERROR! Cannot override
}

final Class

final class FinalClass {
    // Cannot be extended
}

class Child extends FinalClass {}  // ERROR!

final Summary

Applied To Effect
Variable Constant, cannot reassign
Method Cannot be overridden
Class Cannot be extended
Key: String, Integer, and all wrapper classes are final!
8. Object Class

java.lang.Object

Root class of all Java classes. Every class implicitly extends Object.

Important Methods

Method Description
toString() String representation
equals(Object) Compares objects
hashCode() Returns hash code
getClass() Returns runtime class
clone() Creates copy (protected)
finalize() Called before GC (deprecated)
wait(), notify(), notifyAll() Thread synchronization

Overriding toString() and equals()

class Person {
    String name;
    int age;
    
    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }
    
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        Person p = (Person) obj;
        return age == p.age && name.equals(p.name);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}
MCQ Tip: If you override equals(), you MUST override hashCode() too!
