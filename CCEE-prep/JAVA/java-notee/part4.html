1. Collections Framework Overview

Collection Hierarchy

Iterable
└── Collection
    ├── List (ordered, duplicates allowed)
    │   ├── ArrayList
    │   ├── LinkedList
    │   └── Vector (synchronized)
    ├── Set (no duplicates)
    │   ├── HashSet
    │   ├── LinkedHashSet
    │   └── TreeSet (sorted)
    └── Queue
        ├── PriorityQueue
        └── LinkedList

Map (separate hierarchy - key-value pairs)
├── HashMap
├── LinkedHashMap
├── TreeMap (sorted)
└── Hashtable (synchronized)

Collection vs Collections

Collection Collections
Interface Utility class
Root of hierarchy Static methods
java.util.Collection java.util.Collections

Common Methods (Collection Interface)

add(E e)           // Add element
remove(Object o)   // Remove element
contains(Object o) // Check existence
size()             // Number of elements
isEmpty()          // Check if empty
clear()            // Remove all
iterator()         // Get iterator
toArray()          // Convert to array
MCQ Tip: Collection is interface (singular). Collections is utility class (plural) with static methods!
2. List Interface

Characteristics

  • Ordered (maintains insertion order)
  • Allows duplicates
  • Index-based access

ArrayList

ArrayList list = new ArrayList<>();

// Add elements
list.add("Apple");
list.add("Banana");
list.add(1, "Cherry");  // at index 1

// Access
list.get(0);            // "Apple"
list.set(0, "Apricot"); // replace

// Remove
list.remove(0);         // by index
list.remove("Banana");  // by object

// Other operations
list.size();            // length
list.contains("Apple"); // check
list.indexOf("Apple");  // find index
list.clear();           // remove all

LinkedList

LinkedList list = new LinkedList<>();

// Additional methods (Deque operations)
list.addFirst("First");
list.addLast("Last");
list.getFirst();
list.getLast();
list.removeFirst();
list.removeLast();

ArrayList vs LinkedList

ArrayList LinkedList
Dynamic array Doubly linked list
Fast random access O(1) Slow random access O(n)
Slow insert/delete O(n) Fast insert/delete O(1)
Less memory More memory (pointers)

Iteration

// For loop
for (int i = 0; i < list.size(); i++) {
    System.out.println(list.get(i));
}

// Enhanced for
for (String s : list) {
    System.out.println(s);
}

// Iterator
Iterator it = list.iterator();
while (it.hasNext()) {
    System.out.println(it.next());
}

// forEach (Java 8+)
list.forEach(s -> System.out.println(s));
Key: Use ArrayList for frequent read. Use LinkedList for frequent insert/delete.
3. Set Interface

Characteristics

  • No duplicates allowed
  • At most one null (HashSet, LinkedHashSet)

HashSet

HashSet set = new HashSet<>();
set.add("Apple");
set.add("Banana");
set.add("Apple");  // Ignored - duplicate

System.out.println(set.size());  // 2
System.out.println(set.contains("Apple"));  // true

LinkedHashSet

// Maintains insertion order
LinkedHashSet set = new LinkedHashSet<>();
set.add("C");
set.add("A");
set.add("B");
// Iteration: C, A, B

TreeSet

// Sorted order (natural ordering)
TreeSet set = new TreeSet<>();
set.add(30);
set.add(10);
set.add(20);
// Iteration: 10, 20, 30

// Navigation methods
set.first();     // 10
set.last();      // 30
set.higher(15);  // 20 (next higher)
set.lower(15);   // 10 (next lower)

Set Comparison

HashSet LinkedHashSet TreeSet
No order Insertion order Sorted order
O(1) operations O(1) operations O(log n) operations
Allows null Allows null No null
MCQ Tip: HashSet uses equals() and hashCode(). TreeSet uses Comparable/Comparator.
4. Map Interface

Characteristics

  • Key-value pairs
  • Keys are unique
  • One null key in HashMap

HashMap

HashMap map = new HashMap<>();

// Add
map.put("Apple", 10);
map.put("Banana", 20);
map.put("Apple", 15);  // Updates value

// Access
map.get("Apple");      // 15
map.getOrDefault("Cherry", 0);  // 0 if not found

// Check
map.containsKey("Apple");
map.containsValue(15);

// Remove
map.remove("Apple");

// Size
map.size();
map.isEmpty();

Iteration

// Keys
for (String key : map.keySet()) {
    System.out.println(key + ": " + map.get(key));
}

// Values
for (Integer value : map.values()) {
    System.out.println(value);
}

// Entries
for (Map.Entry entry : map.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}

// forEach (Java 8+)
map.forEach((k, v) -> System.out.println(k + ": " + v));

TreeMap (Sorted by Key)

TreeMap map = new TreeMap<>();
map.put("Cherry", 30);
map.put("Apple", 10);
map.put("Banana", 20);
// Keys in order: Apple, Banana, Cherry

map.firstKey();    // "Apple"
map.lastKey();     // "Cherry"

Map Comparison

HashMap LinkedHashMap TreeMap
No order Insertion order Sorted by key
O(1) O(1) O(log n)
1 null key 1 null key No null key
Key: HashMap allows one null key and multiple null values. Hashtable allows NO null!
5. Threads - Basics

What is a Thread?

Lightweight subprocess, smallest unit of processing. Java supports multithreading natively.

Creating Threads - Extending Thread

class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Thread running: " + getName());
    }
}

MyThread t = new MyThread();
t.start();  // Don't call run() directly!

Creating Threads - Implementing Runnable

class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("Runnable running");
    }
}

Thread t = new Thread(new MyRunnable());
t.start();

// Lambda version (Java 8+)
Thread t2 = new Thread(() -> System.out.println("Lambda thread"));
t2.start();

Thread vs Runnable

extends Thread implements Runnable
Cannot extend other class Can extend other class
Each thread = new object Same runnable, multiple threads
In-built thread methods Need Thread object for methods

Thread Methods

Method Description
start() Start thread execution
run() Entry point for thread code
sleep(ms) Pause thread (static)
join() Wait for thread to finish
yield() Suggest giving up CPU
getName()/setName() Get/set thread name
getPriority()/setPriority() Thread priority (1-10)
isAlive() Check if thread is running

Thread Lifecycle

NEW → RUNNABLE → RUNNING → BLOCKED/WAITING → TERMINATED
         ↑_____________________________|
MCQ Tip: Call start() not run()! Calling run() directly won't create new thread.
6. Thread Synchronization

Why Synchronization?

Prevent race conditions when multiple threads access shared resources.

synchronized Method

class Counter {
    private int count = 0;
    
    public synchronized void increment() {
        count++;  // Thread-safe
    }
    
    public synchronized int getCount() {
        return count;
    }
}

synchronized Block

class Example {
    private Object lock = new Object();
    
    void method() {
        synchronized(lock) {
            // only one thread can execute this block
        }
    }
    
    void method2() {
        synchronized(this) {
            // lock on current object
        }
    }
}

volatile Keyword

class SharedData {
    volatile boolean flag = false;
    // Changes visible to all threads immediately
}

wait(), notify(), notifyAll()

class Buffer {
    private int data;
    private boolean hasData = false;
    
    synchronized void produce(int value) throws InterruptedException {
        while (hasData) {
            wait();  // Wait until consumed
        }
        data = value;
        hasData = true;
        notify();  // Notify consumer
    }
    
    synchronized int consume() throws InterruptedException {
        while (!hasData) {
            wait();  // Wait until produced
        }
        hasData = false;
        notify();  // Notify producer
        return data;
    }
}

Thread Safety

Class Thread-Safe?
ArrayList No
Vector Yes (synchronized)
HashMap No
Hashtable Yes (synchronized)
StringBuilder No
StringBuffer Yes (synchronized)
Key: wait(), notify(), notifyAll() must be called from synchronized context!
7. Deadlock and Thread States

Deadlock

Two or more threads waiting for each other forever to release resources.

// Thread 1 holds lock A, waits for lock B
// Thread 2 holds lock B, waits for lock A
// = DEADLOCK!

// Avoid by:
// 1. Acquiring locks in same order
// 2. Using timeouts
// 3. Using tryLock()

Thread States (Thread.State)

State Description
NEW Thread created, not started
RUNNABLE Executing or ready to execute
BLOCKED Waiting to acquire lock
WAITING Waiting indefinitely (wait(), join())
TIMED_WAITING Waiting with timeout (sleep(), wait(ms))
TERMINATED Completed execution

Thread Priority

Thread t = new Thread();
t.setPriority(Thread.MAX_PRIORITY);  // 10
t.setPriority(Thread.MIN_PRIORITY);  // 1
t.setPriority(Thread.NORM_PRIORITY); // 5 (default)

Daemon Threads

Thread t = new Thread();
t.setDaemon(true);  // Set before start()
t.start();

// Daemon threads are background threads
// JVM exits when only daemon threads remain
MCQ Tip: sleep() doesn't release lock. wait() releases lock!
