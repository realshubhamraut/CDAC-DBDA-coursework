Java Programming Notes
Part 3: Inner Classes, Interfaces & Packages

1. Inner Classes (Nested Classes)

Types of Nested Classes

Type Description
Member Inner Class Non-static class inside another class
Static Nested Class Static class inside another class
Local Inner Class Class inside a method
Anonymous Inner Class Class without name, declared and instantiated together

Member Inner Class

class Outer {
    int x = 10;
    
    class Inner {
        void display() {
            System.out.println("x = " + x);  // Can access outer members
        }
    }
}

// Creating inner class object
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
inner.display();

Static Nested Class

class Outer {
    static int x = 10;
    int y = 20;
    
    static class StaticNested {
        void display() {
            System.out.println("x = " + x);  // Can access static only
            // System.out.println(y);  // ERROR! Cannot access non-static
        }
    }
}

// No need for outer instance
Outer.StaticNested nested = new Outer.StaticNested();
nested.display();

Local Inner Class

class Outer {
    void method() {
        final int localVar = 100;  // effectively final
        
        class LocalInner {
            void display() {
                System.out.println(localVar);
            }
        }
        
        LocalInner li = new LocalInner();
        li.display();
    }
}

Anonymous Inner Class

// With interface
interface Greeting {
    void greet();
}

Greeting g = new Greeting() {
    @Override
    public void greet() {
        System.out.println("Hello!");
    }
};
g.greet();

// With abstract class
abstract class Animal {
    abstract void sound();
}

Animal a = new Animal() {
    @Override
    void sound() {
        System.out.println("Bark");
    }
};

Inner Class Comparison

Feature Member Static Nested Local Anonymous
Access outer instance ✓ ✗ ✓ ✓
Can have static members ✗ ✓ ✗ ✗
Can be abstract ✓ ✓ ✓ ✗
Key: Local/anonymous classes can only access local variables that are final or effectively final!
2. Interfaces

What is an Interface?

A contract/blueprint that specifies what a class must do, but not how. Supports multiple inheritance.

Interface Declaration

interface Drawable {
    // Constants (implicitly public static final)
    int MAX = 100;
    
    // Abstract methods (implicitly public abstract)
    void draw();
    
    // Default method (Java 8+)
    default void show() {
        System.out.println("Showing...");
    }
    
    // Static method (Java 8+)
    static void info() {
        System.out.println("Drawable interface");
    }
    
    // Private method (Java 9+)
    private void helper() {
        // helper code
    }
}

Implementing Interface

class Circle implements Drawable {
    @Override
    public void draw() {
        System.out.println("Drawing circle");
    }
}

// Multiple interfaces
class Rectangle implements Drawable, Printable {
    // Must implement all abstract methods
}

Extending Interfaces

interface A {
    void methodA();
}

interface B extends A {
    void methodB();
}

// Interface can extend multiple interfaces!
interface C extends A, B {
    void methodC();
}

Functional Interface (Java 8+)

@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
    // Only ONE abstract method allowed!
}

// Can use lambda expression
Calculator add = (a, b) -> a + b;
System.out.println(add.calculate(5, 3));  // 8

Interface vs Abstract Class

Interface Abstract Class
implements keyword extends keyword
Only public members Any access modifier
No constructors Can have constructors
Variables: public static final Any type of variables
Multiple inheritance ✓ Single inheritance only
Methods: abstract, default, static abstract + concrete methods
MCQ Tip: Interface variables are implicitly public static final. Interface methods are implicitly public abstract.
3. Packages

What is a Package?

A namespace that organizes classes and interfaces. Prevents naming conflicts and controls access.

Creating a Package

// File: com/example/MyClass.java
package com.example;  // Must be first statement

public class MyClass {
    public void display() {
        System.out.println("Hello from package!");
    }
}

Importing Packages

// Import specific class
import java.util.ArrayList;

// Import all classes from package
import java.util.*;

// Static import
import static java.lang.Math.*;

// Use class
ArrayList list = new ArrayList<>();
double result = sqrt(16);  // static import

Built-in Packages

Package Contains
java.lang Core classes (String, Math, Object) - auto imported
java.util Collections, Date, Scanner, Random
java.io I/O classes (File, Stream)
java.net Networking (URL, Socket)
java.sql JDBC classes
java.awt GUI classes

Package Access

// Same package - default access works
package com.example;
class A { }  // accessible within com.example

// Different package - need public
package com.other;
import com.example.A;  // ERROR if A is not public

Classpath

// Compile with package
javac -d . MyClass.java

// Run
java com.example.MyClass
Key: java.lang is automatically imported. You don't need import java.lang.*;
4. Exception Handling

Exception Hierarchy

Throwable
├── Error (serious, not handled)
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── ...
└── Exception
    ├── RuntimeException (unchecked)
    │   ├── NullPointerException
    │   ├── ArrayIndexOutOfBoundsException
    │   ├── ArithmeticException
    │   └── ...
    └── Checked Exceptions
        ├── IOException
        ├── SQLException
        └── ...

Checked vs Unchecked

Checked Unchecked
Compile-time check Runtime check
Must handle or declare No mandatory handling
IOException, SQLException RuntimeException and subclasses

try-catch-finally

try {
    // risky code
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
} catch (Exception e) {
    System.out.println("General exception: " + e.getMessage());
} finally {
    // always executes
    System.out.println("Cleanup code");
}

Multiple Exceptions (Java 7+)

try {
    // code
} catch (IOException | SQLException e) {
    // handle both
}

throw vs throws

// throw - throws an exception
void divide(int a, int b) {
    if (b == 0) {
        throw new ArithmeticException("Cannot divide by zero");
    }
}

// throws - declares exceptions
void readFile() throws IOException {
    // may throw IOException
}

try-with-resources (Java 7+)

// Auto-closes resources
try (FileReader fr = new FileReader("file.txt");
     BufferedReader br = new BufferedReader(fr)) {
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// No need for finally to close!

Custom Exception

class InvalidAgeException extends Exception {
    public InvalidAgeException(String message) {
        super(message);
    }
}

void validateAge(int age) throws InvalidAgeException {
    if (age < 0) {
        throw new InvalidAgeException("Age cannot be negative");
    }
}

Common Exceptions

Exception Cause
NullPointerException Accessing null reference
ArrayIndexOutOfBoundsException Invalid array index
ArithmeticException Division by zero
ClassCastException Invalid casting
NumberFormatException Invalid number parsing
IllegalArgumentException Invalid method argument
FileNotFoundException File not found
MCQ Tip: throw is used to throw exception, throws is used to declare in method signature.
5. Exception Handling Rules

Catch Ordering

// Most specific to most general
try {
    // code
} catch (FileNotFoundException e) {
    // specific first
} catch (IOException e) {
    // then more general
} catch (Exception e) {
    // most general last
}

Override Rules with Exceptions

class Parent {
    void method() throws IOException {
        // code
    }
}

class Child extends Parent {
    @Override
    void method() throws FileNotFoundException {
        // Can throw same or narrower exception
        // Cannot throw broader exception!
    }
}

finally Behavior

// finally always runs (except System.exit())
int test() {
    try {
        return 1;
    } finally {
        return 2;  // This is returned!
    }
}
// Returns 2, not 1!

Exception Propagation

void method1() {
    method2();  // exception propagates up
}

void method2() {
    throw new RuntimeException();  // unchecked - no need to declare
}
Key: Overriding method cannot throw broader (parent) exception than the overridden method!
